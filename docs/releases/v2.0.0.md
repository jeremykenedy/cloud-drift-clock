# Cloud Drift Clock 2.0.0

Real sunset cloud flight replaces the photograph pan. Nearby vapor, distant mountains and camera banking come from licensed moving footage. The optional clock remains independently configurable, and all media plays offline.

## Upgrade guide

Upgrade from 1.1.0, 1.0.1 or 1.0.0 by installing the signed APK in place with the same production signer. Android version code 5 is higher than those releases. Do not uninstall first: uninstalling deletes saved settings.

```bash
shasum -a 256 -c cloud-drift-clock.apk.sha256
adb -s TV_SERIAL install -r cloud-drift-clock.apk
```

The package, DreamService, settings activity, provider authority and nine preference keys remain unchanged. Existing clock visibility, including its earlier implicit On default, is preserved. Turn Show clock off for word-free flight. Recheck the speed setting because it now controls film playback. No database migration, credentials, runtime download or system-timer change is required.

Rollback requires uninstalling the newer app before installing an older Android version code, which deletes its preferences. Prefer a later compatible update when preserving preferences matters.

## Breaking changes

- Palette and density remain stored and validated but no longer alter the scene. They are hidden as native controls and identified as inactive in the provider schema. Filmed scenery retains its photographed light and cloud cover.
- The stored speed choices now mean actual playback: `slow` is 0.75x, `gentle` is 1x and `drifting` is 1.25x. Labels show those rates. Slow motion retains source frames longer rather than generating interpolated frames.
- There is one sunset cinematic flight, not artificial day/night weather or a choice of cloud populations. This public behavior change warrants a major version.

## Major changes

- Bundled 1080p H264 cloud flight with a 720p decoder fallback and no runtime network permission.
- Actual near-cloud camera motion, independently drifting optional time and meaningful playback controls.
- Remote-accessible offline media attribution and complete licenses outside the scene.

## Minor changes and fixes

- Durable settings-provider writes finish before success is reported.
- Pause/surface loss releases the decoder; resume restores playback position.
- Credits opens with Close focused; Up reads the text and Right returns focus to Close.
- Current native screenshots, in-app poster, theme/mobile banners and reduced-motion stills replace the earlier artwork claims.

## Verification and limits

Physical Fire TV AFTALMO/API 28: same-signer update retained all nine provider values; seven native D-pad controls, clock Off with randomization, visible clock drift, Preview/Back and two actual non-test Dreams passed. The unchanged five-minute idle path attached after 300.383 seconds (slow/Off) and 300.948 seconds (fast/On).

Final code 5 passed its exact installed hash, retained settings, native Credits scrolling/Right/Close, word-free Preview, an eight-second moving capture and Back. Fresh surrounding launcher/provider/system/external-file state was restored. Renderer/clock/provider classes and all media remain equivalent to the earlier full Dream test; only Credits UI, version metadata and the poster changed. See [device verification](https://github.com/jeremykenedy/cloud-drift-clock/blob/v2.0.0/docs/VERIFICATION.md).

The source is 25fps. Three short fast/clock-on window samples measured 34.208-35.046 composite presents/second, including clock updates; this is not video FPS. Slow-case presentation sampling was unavailable. Decoder counts reported zero dropped frames in both short Dream windows. Native 4K, other TV models, sustained thermal behavior and power use remain unverified.

The 34-second loop uses a disclosed 1.2-second dissolve. Camera banking and sunset color remain. This is an edited loop, not a naturally closed flight path. Required film credit and CC BY 3.0 terms are retained; source audio/music is excluded.

The app collects and transmits no usage, identity, diagnostic or crash data. It has no runtime Internet permission or reporting SDK.
